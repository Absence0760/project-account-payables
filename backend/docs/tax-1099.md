# 1099 tracking & reporting (US tax compliance)

US AP teams need to file IRS 1099-NEC (contractor payments) and/or
1099-MISC forms for any vendor they pay ≥ $600 in a calendar year. This
doc covers what's shipped, what the tenant has to do manually, and how
to add real e-filing when a customer needs it.

## What's shipped

### Data model

Five columns added to ``vendors`` (migration `0011_vendor_1099_fields`):

| Column | Purpose |
|---|---|
| `tax_classification` | IRS entity type from W-9 box 3 (`individual`, `sole_proprietor`, `llc_s_corp`, `llc_c_corp`, `llc_partnership`, `c_corp`, `s_corp`, `partnership`, `trust`, `other`). |
| `is_1099_eligible` | Flag set by AP when collecting W-9. C-corps / S-corps are **not** 1099-eligible for services; we don't auto-derive because corporate exceptions (legal, medical) and tenant judgement apply. |
| `w9_received_date` | Date the AP team accepted the W-9. |
| `w9_file_key` | S3 key for the uploaded PDF. Null if not yet received. |
| `tin_verified_at` | Timestamp of the last successful IRS TIN match. Null until the Tax1099 integration lands. |

The existing `tax_id` column (VARCHAR(50)) already holds the TIN /
EIN / SSN from the W-9 box 1–2.

### API

All endpoints are `admin` + `ap_manager` (the report also allows `cfo`):

| Endpoint | What it does |
|---|---|
| `GET /api/tax/1099-report?year=YYYY` | Per-vendor aggregate of completed payments in the calendar year, flagged if ≥ $600 and if a W-9 is on file. |
| `POST /api/tax/vendors/{id}/w9` | Upload the signed W-9 PDF, set `w9_received_date`, flip `is_1099_eligible`. |
| `PATCH /api/tax/vendors/{id}/w9` | Update tax fields without re-uploading (e.g. marking a vendor 1099-ineligible after a legal review). |

### Report structure

```json
{
  "year": 2026,
  "generated_at": "2026-04-23",
  "threshold_usd": "600",
  "vendor_count_total": 42,
  "vendor_count_eligible_over_threshold": 8,
  "vendor_count_over_threshold_without_w9": 2,
  "total_reportable_usd": "87450.00",
  "rows": [
    {
      "vendor_id": "...",
      "vendor_name": "Jane Consultant",
      "tax_id": "123-45-6789",
      "tax_classification": "sole_proprietor",
      "is_1099_eligible": true,
      "w9_received_date": "2026-01-15",
      "w9_on_file": true,
      "ytd_paid": "12000.00",
      "over_threshold": true,
      "payment_count": 12
    }
  ]
}
```

Aggregation rules:
- Only `Payment.status == 'completed'` is counted.
- Bucketed by `Payment.completed_at` (year-of-payment, not year-of-
  invoice — this is what the IRS wants).
- Reversed / voided payments are not netted out. When we add a
  payment-reversal flow, this aggregate needs updating.
- Vendors with zero payments still appear — handy for "which vendors
  do I need to collect W-9s from" triage, even if they're under
  threshold.

## What the tenant does each year

Typical January workflow for a US tenant:

1. **Collect missing W-9s.** Run the report for the prior year.
   Filter rows where `over_threshold=true` and `w9_on_file=false`.
   Email those vendors; upload the returned PDFs via
   `POST /api/tax/vendors/{id}/w9`.
2. **Confirm 1099-eligibility flags.** Vendors paid > $600 but marked
   `is_1099_eligible=false` (typically because they're a corporation)
   need a human sanity check. Exceptions: legal services, medical
   payments, and certain gross-proceeds rows are 1099-eligible even
   for corporations.
3. **Export the filtered report** — CSV export from the UI, or pipe
   the JSON to Tax1099. For pilot #1, hand-export + upload to
   Tax1099's web UI is fine.
4. **File by January 31** — IRS deadline for 1099-NEC to vendor AND
   copy-A to IRS. 1099-MISC deadline varies by box type.

## What's NOT shipped (founder roadmap)

### TIN matching (IRS validation)

The IRS offers free TIN matching via the TIN Matching Bulk Request
service. Two approaches:

- **Direct**: Register for IRS TIN Matching → upload batch → poll for
  results. Free but manual.
- **Via Tax1099**: Their `/api/tin-match` endpoint wraps the IRS
  service. ~$1 per match. Their SDK is a single HTTP call.

Add a `services/tin_matching.py` adapter (start with `tax1099`) and a
`POST /api/tax/vendors/{id}/tin-match` endpoint that updates
`tin_verified_at` on success. Low priority for pilot #1 — tenants can
run one-off TIN matches via Tax1099's web UI.

### E-filing with the IRS

Don't build this from scratch. Use Tax1099 (getform.io) — it handles:

- IRS e-file transmission + state filings
- Copy B to vendor (PDF + USPS mail option)
- W-9 collection portal (vendors fill and sign online)
- TIN matching
- Corrections filings (1099-C)

Integration sketch:
1. Get Tax1099 API key (signed contract + KYC).
2. Persist their API key in `Organization.settings.tax.tax1099_api_key`
   per tenant.
3. Add `services/tax_1099_filing.py` with:
   - `submit_1099_batch(tenant, year) -> batch_id`
   - `get_batch_status(tenant, batch_id)`
4. Add endpoint `POST /api/tax/1099-report/{year}/submit` that calls
   the service and stores the batch_id on `Organization.settings.tax`.

Pricing reference (2026): ~$3 per 1099-NEC for e-file + postal mail.

### W-9 self-service for vendors

Today: AP collects W-9 via email, uploads PDF to our endpoint.

Future: The supplier portal already exists (see
`backend/docs/supplier-portal.md`). Add a "W-9" tab where vendors can:
- Fill the form in-app (vendor supplies classification + TIN + sign)
- Upload their own signed PDF
- Get notified when it's about to expire (W-9s are valid until vendor
  info changes — no strict expiry)

This is the right long-term answer for scale — stops the AP team from
chasing W-9s manually. Defer until you have >1 customer whose AP lead
is annoyed enough to ask.

### State filing

Several states (California, Oregon, Massachusetts, others) have their
own 1099 filing requirements. Tax1099 handles them when you pick the
"Combined Federal/State Filing" option. Nothing to build on our side;
just set the flag in the Tax1099 submit call.

### International contractor forms

Non-US vendors require W-8BEN / W-8BEN-E instead of W-9. Same data
model works (add "w8_ben" and "w8_ben_e" values to
`tax_classification`), but the reporting form is 1042-S, not 1099.
Scope this when the first customer pays a non-US contractor.

## Testing

Run the report against the seed data:

```bash
# Seed creates Acme + TechFlow tenants with sample vendors + payments.
# The two `completed` payments in seed data are stamped 2024-03-25 and
# 2024-03-20, so the report has content only when year=2024.
cd backend && python scripts/seed.py
# Against the Acme tenant API:
curl -H "Authorization: Bearer $TOKEN" \
     -H "X-Tenant-Slug: acme" \
     "http://localhost:8000/api/tax/1099-report?year=2024"
```

The seeded vendors have `is_1099_eligible=false` by default — the
report lists every vendor but `vendor_count_eligible_over_threshold`
will be 0 until a W-9 is attached via
`POST /api/tax/vendors/{id}/w9`. This is correct behaviour for a
fresh tenant.
